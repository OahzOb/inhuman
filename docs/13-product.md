# inhuman — 产品说明

> 本文只描述产品层面的**设计原则、已有功能和未来规划**。它不涉及具体技术栈、框架、模块划分，或某个功能的代码实现；但保留通用的协议名、服务名和计算机术语（如 SSH、MCP、token、检查点），因为它们是产品能力的一部分。技术实现见 `docs/` 的其他文档。

## 一句话

**inhuman 是一个本地优先的智能助手：每段对话都在一个工作区里运行，助手只能在这个工作区里读写文件；默认不打断你；唯一能让助手在另一台机器上执行操作的，是你明确打开的远程能力。**

它是单用户的、不需要账号的、把“能力边界”当作产品本身来做的工具。

---

## 一、设计原则

### 1. 工作区是产品的边界

- 每段对话绑定一个工作区；助手只能看到、只能改这个工作区。
- 这不是靠提示词要求模型“别乱来”，而是产品只给它这个入口：它拿不到工作区之外的位置。
- 用户导入文件是**复制**，不是移动；原件永远不动，也不在目录里。所以工作区里导入的文件坏了、删了，原件还在。
- 结论：工作区内的操作默认是可逆的；这才有第 3 条“默认不审批”。

### 2. 本地能力硬隔离，外部能力默认关闭

- Agent 的本地能力被硬限制在工作区内：它只能读写这个工作区，拿不到工作区之外的路径。唯一的远程操作能力是 SSH，默认关闭。
- 没有“解锁更多本地权限”的开关，也没有“高级模式”或可累积的权限等级；能力边界不靠用户选择档位来改变。
- 要避免的是**由权限开关造成的会话不连续**：每执行一条命令问一次、每换一个模式就改变对话的含义、每加一个能力就多一个需要用户理解的档位。这些会把一次对话切成一串审批，也会训练用户无脑点过。
- **工具清单按回合固定**：只有用户能在回合边界改变一段对话的工具清单；模型不能给自己加能力，消息和工具结果也不能。改动从下一回合生效，不会在流式回答中途改变规则。
- 对 SSH 这类高风险能力，默认走**一次性的能力授权**：第一次调用时，用最强的提示说明主机、用户和第一个操作；用户确认后，这段对话就获得用户所选中的 SSH 工具的使用授权，之后按普通规则执行，默认不再逐条询问。
- 工具清单和 SSH 授权是两层：清单决定这个回合有哪些工具；授权只回答“这段对话能不能用清单里选中的远程工具”，不会把未选中的 SSH 工具加进来。
- 为什么不是逐条问：用户通常无法判断一串 shell 命令该不该执行；对一条命令问“确定吗”，得到的往往不是判断，而是习惯性点击。一次授权加可撤销，比一百次无法回答的询问更接近真实的安全。
- 这不是设备级权限：授权范围是**这段对话 + 用户选中的 SSH 工具**，不是设备、不是本地文件系统、不是所有对话；用户可以随时撤销，关闭全局开关会清掉所有授权。所谓“最高权限”，是这组工具授权范围内的最高，不是设备级的最高。
- 但“询问”仍然是用户的权利：用户可以把任意工具、任意助手、任意路径设成“询问”；默认不问，不等于不能问。默认只是“不主动打断”，是否打断由用户决定。
- 判断标准：新增一个能力时，不要新增一个“模式”或“权限档位”；如果要问，就问一次、问在能力被授予的地方，而不是在每条命令前重复问。

### 3. 默认不打扰

- 默认不弹审批，包括删除文件。
- 用户想更谨慎时，可以按工具、按助手、按路径收紧；多处规则同时生效时，**取最严**。
- 默认不问，不等于“永远不问”：询问是用户的权利。用户可以要求每次调用都问；代价是会话会被打断，所以这个选择由用户显式做出，而不是产品默认。
- 没有“删除永远要问”的地板；用户是工作区的主人，包括决定删文件要不要问。
- 为什么：工作区里是副本，问“确定吗”答案永远是“确定”；一个总是得到同一个答案的对话框不是安全措施，是摩擦。审批疲劳会让真正需要确认的时刻被无脑点过。
- 审批是**可选的收紧手段**，不是主要安全机制；主要机制是第 1 条的结构。

### 4. 用户对自己的数据有主权

- 用户永远能读写自己的工作区；路径规则只限制助手，不限制用户。
- 工作区的绝对位置只给用户看，不进入模型上下文。
- 用户可以通过应用导入、导出、编辑，也可以用系统文件管理器或外部编辑器打开。
- 应用不要求广泛存储权限，也不接管用户的整个文件系统。

### 5. 花钱和远程必须显眼

- 付费工具在**选择它的地方**和**使用它的地方**都有明确标记和说明；价格不写在没人展开的描述里。
- 付费披露不等于审批：默认仍然不问，是否先问由用户规则单独决定。
- 远程能力有独立标记；它不能混进本地工具列表里，也不能靠“全选”被顺带打开。
- 这条对以后所有“调用第三方付费服务”或“影响设备之外”的能力都生效，不只是现在这些。

### 6. SSH 是第一个被批准的远程操作例外

- 默认关闭，而且是多层关闭：全局开关默认关；即使打开，助手还必须显式选中要用的远程工具族；第一次调用时，对话里再授权一次。选择界面按族呈现，SSH 拆成**只读**与**执行/写入**两族、两个总开关：打开只读不会顺带打开执行/写入。
- 首次授权后，默认不再逐条询问；如果用户把 SSH 的规则设成“询问”，才会逐条确认。授权是能力授予，审批是单次许可，两者可以叠加，但默认只需要前者。
- 网页搜索/抓取和 URL 下载都由应用代用户发请求，不把网络交给助手；请求内容、限制和授权在下面分别说明。搜索/抓取可以走付费提供商，也可以走免费的本机搜索/抓取（请求由应用从手机网络发出）。SSH 不同，它让助手在另一台机器上读、写、执行。
- 应用保存的是**地址簿**：多台主机的别名、地址、端口、用户名和可选指纹，**不保存密码或私钥**。每个对话再单独勾选"把哪几台告诉 agent"；`ssh_hosts` 只返回这些信息，不连接、不含凭据。连接凭据由 agent 在调用里给出（工作区密钥或密码），所以任何一次调用都不会用到 app 保存的凭据。
- 只读族（主机清单、探测、列目录、读文件、下载）是一个开关，不需要开命令执行；执行/写入族（执行命令、上传、写远端）是另一个开关，打开会让授权重置、下一次重新确认。
- 凭据参数在写入会话前隐藏；命令文本、路径和写入内容会留在会话里，这是会话本身。
- 风险在远端，不在工作区副本：远端删除、覆盖、改权限都可能不可逆。所以远程写操作不提供回退。
- 这不是设备级权限：没有本地权限提升，没有可累积的权限层级，只有一个用户显式打开、按对话授权、可撤销的远程通道。

### 6.1 URL 下载是第二个被批准的例外，默认关闭

- 助手可以调用 `download_url`，让 app 从一个 https URL 抓取文件并保存到这段对话的 `downloads/` 目录；助手自身仍然没有网络，app 代它请求。
- 默认关闭，同样是三层：Settings 全局开关默认关；打开后助手必须显式选择这个工具；每段对话第一次调用弹专用授权，显示 URL 和 host，并说明“URL 可以把数据带出去”，允许后写入该对话的下载授权，之后走普通工具策略。聊天菜单可撤销，全局开关关闭会清空所有对话的授权。
- 硬限制：仅 https；只接受公网地址（私网、回环、链路本地、CGNAT、保留段一律拒绝，DNS 解析和每次重定向都重新检查）；单文件 64 MiB；落在 `downloads/`，不覆盖同名文件；工作区配额、文件数和预留空间照常；只发 GET，没有 cookie、凭据、自定义头和 POST；下载的内容不会被自动读取或执行。
- 它和 `web_fetch` 的区别：`web_fetch` 返回网页正文进上下文，由付费后端打开页面；`download_url` 保存字节到工作区，由 app 自己的 HTTP 客户端请求。
- 风险如实说：URL 的 path 和 query 是任意字符串，提示注入可以让模型把内容编码进 URL 再请求，从而免费外传。授权对话框、Settings 说明和工具描述都写明这一点；这是被接受的残余风险，换的是“agent 能帮忙下载任何公开链接”。

### 6.2 本机网页抓取是第三个被批准的例外（本机搜索不是例外）

- 付费搜索/抓取由提供商发起请求；免费选项让应用自己从手机网络请求，所以不需要搜索 API 密钥。它分成两个工具：**本机搜索** `web_search_local`（只接关键词，读 DuckDuckGo/Bing 的公开结果页）不是例外，属于“用户显式打开、由应用代发的只读内容源”；**本机抓取** `web_fetch_local`（模型给 URL，应用取回正文）是第三个被批准的例外。
- 本机抓取的门禁与 URL 下载同形：Settings 全局开关默认关、助手显式选择、每段对话首次调用弹授权（显示 URL 和 host，说明 URL 可把数据带出去、正文会进入对话、请求从手机网络发出），授权记在对话上，聊天菜单可撤销，全局关闭清空。抓取的实现可以选择“渲染”（用应用的一次性浏览器引擎加载页面），页面脚本会执行，但没有注入 JS 桥、没有登录态/cookie 注入，用后销毁。
- 硬限制：仅 https；只接受公网地址（DNS 解析和每次重定向都检查）；只发 GET，没有 cookie、凭据、自定义头或 POST；响应与正文有上限，只返回可见文本，不返回原始 HTML，不保存文件、不执行页面内容。搜索和抓取共用 URL 下载的那一套地址检查与工具策略（`GuardedHttp` / `DownloadUrl`），不新增第二份规则。
- 本机搜索没有每对话授权，因为参数只有关键词、没有 URL，和 B 站只读同类；它的失败（被风控、非结果页）会如实报错，不伪装成“没有结果”。
- 已知限制：这一版没有客户端限速/每回合次数上限；免费工具没有付费工具的成本闸门，引擎自身的风控是唯一约束，后续会补。

### 7. 可逆与不可逆要分清

- 本地文件操作可还原：每个回合、每个完成的工具组都有还原点（checkpoint）；可以回到“你的消息之前”或“某个工具组之后”。
- 不可逆的远程操作（执行命令、上传、写远端）不提供回滚；含这些操作的回合只允许重新回答，不允许“编辑消息”。
- 还原点按回合保留，用户可以选择保留 1/3/5/10 个回合；调低保留数会先确认，因为较旧回合的快照会立即删除；回退前会列出会改动哪些文件。

### 8. 中断、崩溃、重开都不能悄悄丢东西

- 已经收到的回答，即使你按停止，也会保存；不会因为“停止”丢掉已经计费的部分。
- 进程被杀、断电、旋转屏幕、切后台，不能出现“回答没了”或“下一条消息报错”。
- 备份恢复在应用启动、数据被打开之前完成；失败会回滚旧数据。
- 每个对话的进度通知互相独立；停止一个不会停错另一个。

### 9. 安全声明必须能被审计

- 开源；围栏有自动化测试；文档记录为什么这样做。
- 诊断日志给用户看、可导出；但**不记录密钥、提示词、文件内容**。
- 能力边界要能一句话说清；说不清的能力不加。
- 一个自称安全却不可审计的实现，说服力有限；这是开源的真正理由。

### 10. 轻量、移动优先

- 手机是主产品，不是把手机做成桌面。
- 不为了桌面把手机做重：不移植桌面专属的插件系统、多主机配置和网页版界面。
- 不做 Android 上的 Linux 命令行环境；不做广泛存储权限。
- 性能预算可以调（工具轮数、调用次数、远程资源上限）；**权限边界不可调**。

### 11. 工作台，不是聊天模板

- 视觉是“暖纸/暖石墨 + 一个信号橙”；等宽字体只用于元数据，不用于正文。
- 用细线分隔，不用满屏卡片；网格只出现在空画布上。
- 宽屏要限制阅读宽度并居中；手机、平板、横屏、方屏都要实际验证，不能只验一种。
- 主操作在手机上可以是悬浮按钮，在中等宽度是标题栏，在双栏是顶栏；同一功能在不同尺寸下用不同位置，是设计，不是不一致。

### 12. 说到的必须做到

- 文档、界面文案、工具描述不能承诺产品没做的事。
- 如果文案和实际行为不一致，按缺陷处理，而不是“改文案了事”。
- 改行为就改文档；否则下一次会有人按旧文档做错决定。
- 新功能先对照这份原则：它是否扩大了助手能碰到的范围？如果是，就需要新的“一句话例外”、披露和授权，而不是一个设置项。

### 判断新功能该不该做

1. 它是否扩大了助手能碰到的东西？如果是，先写一句用户能读懂的能力声明，并为它设计披露和授权；不要直接加设置项。
2. 它是否引入了一个“可以要更多权限”的入口？如果是，不做。
3. 它是否可逆？不可逆就明确标记，并且不提供回退。
4. 用户能不能自己验证它？不能验证的能力，先补日志/审计。
5. 它是否只在桌面成立？如果是，先问“手机用户是否也需要”；不需要就不做。
6. 它是否用反复询问来代替一次性能力披露？如果是，改成一次授权。它是否让默认状态多了一次打断？默认仍然是“不打断”，把选择权交给用户。

## 二、已有功能

### 1. 对话与回答

- 流式回答；显示推理过程（模型提供时）、Markdown、代码高亮、token 用量。
- 持续会话（新对话默认）：应用替你维护“这一次请求给模型看什么”。完整记录永远不删；较早的回合折进一份可查看、可重建的**会话简报**，最近的回合保留原文。整理只在回合正常结束且对话可见时发生，可能偶尔多发一次或几次模型请求，用量记在设置 → 用量 → **会话整理**；每段对话都可以停止维护，已有对话保持经典模式、不会自动升级。从聊天菜单可以切换经典 ↔ 持续，并打开**会话记忆**：简报全文、覆盖范围、整理花费、**重建**、**停止维护**和原文搜索。
- 只读记录检索（持续会话自带）：模型可以按关键词搜索当前对话的用户和助手正文，拿到消息编号和片段，必要时按编号读全文。它只读、本地、免费，不联网、不跨对话；读到的全文只进入当次请求，不写进记录（记录里只留一行“查过什么”）。这样简报丢掉的细节仍然找得回来；经典模式下模型本来就能看到完整记录，不需要这个工具。
- 角色扮演场景（手机端）：助手可以带一张**角色卡**（身份与背景、性格与说话方式、默认场景、开场白、示例对白、边界、作者注记，以及可选的温度 / top-p / 回复 token 上限）。首页“新建角色扮演场景”可以从**助手角色卡**开始，也可以从**永久工作区里的资料文件夹**开始：`rp/<故事>/card.json` 加可选的 `scene.json`，对话框会浏览文件夹并用同一套校验（与 `rp_validate` 相同）检查；助手仍然要选，因为模型、服务商和工具上限从它复制，卡里没有名字时也用它兜底。从文件夹建场景会让对话**留在那个永久工作区**（方便以后给文件工具继续改资料），工具仍默认关闭。角色卡编辑器里的“导出到工作区”会把当前卡写到 `rp/<文件夹>/card.json`，已有文件不会被覆盖——这是旧数据库角色卡的迁移路径。**场景创建时会冻结当时的助手提示词、名字和角色卡**，之后编辑助手或资料文件都不会改写已经开始的故事；场景设定里的“重新读取角色卡与助手提示词”是唯一的显式刷新入口。角色卡和场景只进入提示词，**不改变工具、审批、SSH 或工作区边界**。**工坊**（应用内置的唯一一个永久工作区）是 agent 准备这类材料的地方：在工坊里、且不是角色扮演场景的对话会自动获得写作辅助工具 `rp_format`、场景校验 `rp_validate`（仅当该对话已有读文件工具时）、**`rp_create_scene`**（只准备一张场景提案卡，用户点“创建并打开”才真正建对话并直接进入），以及读/起草 app 配置的一组辅助（详见 §3）；这些辅助不可选择、不扩大能力，也不出现在普通工作区，纯角色扮演场景没有工具时也不会出现。由提案创建的场景绑定工坊这个永久工作区，`tools` 仍是显式空列表，资料和对话留在一起。持续会话在场景里用**故事状态简报**（剧情、人物关系、世界细节、未决线索、连续性、玩家角色），而不是任务简报；`/ooc` 开头的行是对助手本人说的，不是场景台词。**场景里的助手回复按剧本文本呈现**：旁白、引号对白、括号/星号动作、`**强调**` 和 `---` 场景切换有不同的字色/字形/分隔线；这是纯显示层——记录、请求、导出、搜索和 Source 原文都不变，也**不要求模型输出特定格式**，模型按自己的习惯写引号/括号/星号即可被识别，没有这些写法的回复就按普通旁白显示。**角色卡可以从文件导入**（角色卡编辑器的「从文件导入…」）：支持外部社区的 PNG（内嵌 CCv2）、JSON（CCv1/v2/v3）和 CHARX，映射身份/性格/情境/开场白/示例对白，`{{char}}` 换成助手名；卡文本里的 HTML 清理为纯文本，**不执行卡内的 HTML/脚本/世界书**——备选开场白、内嵌世界书、扩展正则和网页界面会在导入结果里逐条说明「未导入」，不会假装导入成功；超出本应用长度上限的字段会截断并报告。原始文件不会留在应用里，需要时重新导入。同一角色卡可以开多段互不共享记忆的场景；多角色群聊不在这一版。
- 上下文仪表（经典模式）：显示上下文窗口用了多少；可以显式压缩旧回合（保留最近两个完整回合，更早的用摘要替代），也可以恢复完整历史。持续会话下这个仪表、压缩按钮和“上下文已压缩”横幅不出现在正常界面里，审计入口是“会话记忆”和请求查看器。
- 分支：重新生成保留旧答案，可以切换。
- 重做与回退：重新回答、从你的消息重来、从某个工具组之后重来、编辑你的消息；还原点；改动文件列表。
- 搜索对话标题和消息内容，跳转到具体消息并高亮。
- 会话内搜索（手机端）：全屏搜索当前对话的用户和助手正文，跳过工具结果；列出匹配数和每条摘要，点一条跳到该消息并高亮。
- 回合快速跳转（手机端）：对话上方的“回合 n/m”显示当前位置；点开是用户消息列表，点一条直接跳到那个回合，当前回合在列表里标出。
- 在对话内直接新建对话（手机端）：顶栏的“+”用当前助手新开一段对话；当前是永久工作区时新对话共享它，临时工作区则新建一个。
- 置顶、重命名、删除；手机端支持多选删除，并可以一键全选或取消全选。
- 断连自动重试：流式请求遇到可恢复的网络或服务端错误时，自动重发当前回合最多 5 次（1、2、4、8、15 秒退避，带抖动），行内提示“正在重试 n/5”；放弃后仍保留手动重试。重发前会丢弃失败尝试已收到的部分文字，不会把两次回答拼在一起；工具调用只在整轮成功后执行，所以重试不会重复写文件或执行 SSH 命令。鉴权、余额、上下文超限和证书错误不重试。
- 工作期间发消息（手机端）：回复还在生成时，输入框保持可用。发送有两种交付方式——**结束后发送**（排队，当前回合结束后自动作为下一轮发出；队列在输入框上方可见、可取消，最多 5 条）或**插入本轮**（当前回合还有下一次模型调用时，在工具组之后、下一次请求之前让模型看到这条消息）。插入的是**真实用户消息**：会落库、在记录里标出，并进入之后的请求；它不是新的回合，也不改变本回合的工具、审批、SSH 或下载授权。没有下一次调用时插入会退回排队并在界面上说明；回合失败时队列保留，由用户逐条决定是否发送。队列只在内存中，进程死亡时丢失的范围与未发送草稿相同。
- 错误恢复：重试（经典模式还可以压缩后重试）、去模型服务设置、复制详情；没有“只能关闭”的死胡同。
- 图片附件（手机端）：可从文件一次多选，或直接调用相机拍照；App 不设张数上限，实际边界是模型服务的请求限制（例如 DeepSeek 每请求 600 张、48 MiB 请求体）；先检查模型是否支持视觉，再发送。
- 把助手回复转成语音（手机端）：每条完成的文字回复下方有扬声器按钮；首次会显示一次付费提示和音色选择，之后**点一下就开始朗读**，再点扬声器可暂停/继续。播放条只有一行：**正在朗读的那句话**、播放/暂停和停止图标，下面一条可拖动的**进度条**和“已读 / 总长”；音色在设置（或首次提示）里选，播放条上不再切换。系统通知栏的媒体通知也实时显示同一句字幕（音色和时间在副标题），锁屏的媒体标题同步显示当前字幕，锁屏进度条可拖动定位。**切换对话不会中断已经开始的合成**：请求在后台完成并写进工作区；已经有语音的回复，扬声器是实心且着色的（点开即播、不再计费），首页对应对话标题旁有一个小扬声器标记。音频按“回复 + 音色”缓存在工作区，重复朗读不再计费；朗读前会去掉 Markdown 标记，代码块和表格只提示一声，不逐字读；字幕按句子切分、按字符数分配时长（语音服务不提供逐字时间戳，所以是跟读估算，不是逐字对齐）。新一轮回复开始时自动停止上一段朗读。设置里可以选择音色（DeepSeek 支持 Stella/Tide，留空用默认），也可以打开“自动朗读新回复”：每轮结束后自动朗读最终回答，开启即表示接受语音后端的按请求计费；失败的回合、被停止的回合和刚打开的历史对话都不会自动读。
- 请求原文查看器（手机端）：可以看到系统提示、工具定义、消息和原始工具调用。
- 时间提示（手机端）：用户消息隔得较久时，在**发给模型的请求**里给这条消息开头加一行发送时间（如 `[2026-11-20 15:26]`），让模型分得清“隔了一夜接着说”和“一直没停”。设置 → `12 / 时间` 可选“间隔较长时”（默认，阈值 5/10/30/60 分钟）、“每条都加”或“不加”；间隔模式下一段对话的第一条消息也会带时间，作为后面的起点。提示只存在于请求里，记录、搜索、导出和回退都保持原话不变，请求原文查看器可以看到它；改设置或改设备时区只会多付一次冷启动。
- 演示模式：没有密钥也能跑通工具循环、结果和收尾总结。
- 导出与分享：单段对话可导出 Markdown（可选是否包含工具调用与结果；推理过程一并写出；附件只列路径，不复制文件），也可以直接走系统分享面板；还可以在预览确认后上传到已配置的局域网/Tailscale 服务端的 `/conversation`（明文，服务端无鉴权）。**对话包**（.zip，含消息、工具调用、推理和附件，只带当前分支）可以导出，并从首页的“新建 → 导入对话包”导入成一段新对话。工作区可导出 zip（对话菜单和工作区详情都可，临时和永久工作区都覆盖），也可以在 Workspaces 里导入 zip 作为新的永久工作区。导出是明文，保存位置由用户选择，不能当备份。

### 2. 助手与模型服务

- 助手：一个可保存的“人设”，包含名称、系统提示、模型服务（provider）、模型、推理强度和工具清单。
- 每段对话选择一个助手；对话创建时复制当时的模型服务和模型，之后编辑助手不会改变已有对话。只有一个助手时直接用它创建，不再弹一个没有选择的选择器。
- 模型服务：内置 DeepSeek；可以添加兼容 OpenAI 接口的第三方服务（预设里包含 OpenCode Zen 和 OpenCode Go）；每个助手选择一个服务；模型列表从服务读取；密钥按服务保存。
- 推理强度按对话可调（服务支持时）。

### 3. 工作区与文件

- 工作区有两种：**临时**（随对话创建和删除）和**永久**（对话删了也保留，可以被多个对话共享）。
- **工坊**是应用内置的**唯一一个永久工作区**：对话列表上方有一个常驻入口，“新建”里也有一项，两处打开同一个工坊页。工坊里、且不是角色扮演场景的对话会自动获得一组**不可选择、无能力的辅助**：`rp_format` 写作格式、`rp_validate` 场景/角色卡校验（仅当该对话已有读文件工具时）、`rp_create_scene` 场景提案（点“创建并打开”才真正创建），以及读助手内容（名字、系统提示词、角色卡）、列出并读取各永久工作区根 `AGENTS.md`、起草助手或 `AGENTS.md` 草稿的三对读写工具（草稿只在你已有的编辑器里预填，只有你点保存才生效）。这些辅助不扩大工具、审批、SSH 或下载授权，也不出现在普通工作区；角色扮演场景里没有它们。工坊是应用功能的一部分：**不能改名、不能删除，也不会被批量删除**；工坊页会说明它是什么、能拿它做什么，清理它请删其中的对话和文件。从工坊提案创建的场景绑定这个工作区，删场景不会删资料。
- 从旧版本升级（数据库 v29）时，旧的“配置工坊”会降级为一个普通永久工作区：其中的对话和文件都保留，只是那些对话不再有配置辅助工具和工坊上下文说明；新工坊里的对话可以继续做同样的事。
- 永久工作区有共享配额：约 256 MB、5,000 个文件；单文件写入约 4 MB，单次读取约 1 MB，列表最多 500 项。
- 8 个文件工具：列目录、读文件、写文件、追加、建目录、移动/重命名、删除、查看文件信息。
- 路径规则四档：自由、询问、**拒绝**（任何调用都被挡下，文件名仍然可见）、**不可见**（连文件名都不出现在助手的列表里）。
- 用户可以把文件导入工作区、导出、在应用内编辑、用系统程序打开。
- 工作区可以导出 zip；Workspaces 里也可以导入一个 zip 作为**新的永久工作区**，不会合并或覆盖已有工作区。
- 手机端还可以从 URL 把文件下载到工作区或用户选择的目录。
- 助手也可以（在用户打开全局开关、给助手选中 `download_url`、并在该对话首次授权之后）让 app 从 https URL 下载文件到工作区 `downloads/` 下：单文件 64 MiB，拒绝私网/回环地址，不覆盖同名文件，下载内容不会被自动执行或读取。请求由 app 发出，助手自身仍然没有网络；授权对话框会说明 URL 可以把数据带出去。
- 文件列表可以在当前文件夹内搜索，按名称、修改时间或大小排序；图片可以在应用内直接预览；导出和删除收在每一行的菜单里，删除不再是一个常驻的一击按钮。
- 工作区的绝对位置只给用户看；助手始终只看到工作区内的相对路径。

### 4. 工具与审批

- 共 46 个工具：11 个文件/文档工具、1 个 PDF 视觉读取工具、1 个 DeepSeek OCR 扫描件读取工具（`read_scanned`，需显式选择、会上传文件、按页计费）、时间、1 个本地 JavaScript 计算工具、1 个工具缺口报告工具（`unavailable_tools`）、2 个付费联网工具、2 个本机 web 工具（`web_search_local` / `web_fetch_local`，免费、默认关闭）、1 个 URL 下载工具（`download_url`，默认关闭、按对话授权）、10 个 B 站只读工具、决策、转写、4 个媒体工具（图片、视频、视频状态、语音）、7 个远程工具 + 1 个只读主机清单工具（`ssh_hosts`）、1 个后续建议工具；其中 10 个按调用计费。扫描版 PDF 可用 `read_pdf_vision`（需显式选择、按页计费）交给当前视觉模型转写，或用 `read_scanned` 走 DeepSeek OCR。另有几个不占可选清单、随条件自动出现的辅助工具：持续会话的只读 `recall`；以及**工坊**里非场景对话附带的九个辅助——`rp_format`、`rp_validate`（仅当该对话已有读文件工具时）、`rp_create_scene`（只准备场景提案，用户点击才创建），和 `app_list_assistants`、`app_read_assistant`、`app_propose_assistant`、`app_list_instructions`、`app_read_instruction`、`app_propose_instruction`（读用户配置、准备草稿，草稿只打开已有编辑器）。它们不可选择、不扩大能力、不花额外请求，也不计入 46 个可选工具。
- 每个会改变状态的工具都带“可回退/不可回退”标记；付费工具带“付费”标记；远程工具带“远程”标记。
- 审批默认全部“自由”；用户可以在三个层面收紧：全局、按助手、按路径；同时生效时取最严。
- “询问”是用户可选项：可以把任意工具设成询问；默认不问是为了不打断会话，不是禁止用户收紧。
- “拒绝”和“不可见”是**拒绝执行**，不是“再问一次”；它们排在“询问”之前。
- 每段对话可以有自己的工具清单：助手是上限，只有用户能改，改完从下一回合生效；模型不能改。
- 工具预算：默认每回合最多 8 轮工具、32 次调用；用户可以调高或调低。
- 用量总览：设置 → 05 / 用量，按今天、7 天、30 天、全部汇总本机仍保存的输入/输出/缓存/推理 token、7 个付费工具的调用次数，以及持续会话的**会话整理**次数与输入/输出 token（来自单独的整理记录，因为整理请求没有消息行）。按天和按对话列出。只统计当前仍保存的记录，已删除或回退的回合、经典模式的手动压缩摘要不计入；不换算价格。

### 5. 远程与付费能力

- 远程（SSH）：7 个工具，覆盖探测主机、列目录、读文件、执行命令、上传、写远端文件、下载。
- 默认关闭；全局开关 + 助手显式选择 + 每对话首次授权，三层。
- 首次授权后默认不再逐条询问；用户把 SSH 工具设成“询问”时才会逐条确认。
- 地址簿可保存多台主机（别名/地址/端口/用户名/可选指纹），不保存凭据；每个对话单独勾选告诉 agent 哪几台，改选择不重置授权；主机指纹首次连接时记住，变更时拒绝连接。
- 远程资源有用户设定的上限：命令超时、输出大小、目录行数、文本读取量；模型只能请求更小，不能更大。
- 联网搜索/抓取：可以分别选择 DeepSeek 或 Exa；使用独立的密钥，和聊天用的密钥分开；按调用计费。
- 本机搜索/抓取（免费，免费选项）：设置里打开后，助手可以在本机网络上搜索（DuckDuckGo 或 Bing 的公开结果页）和抓取单个网页，不需要搜索 API 密钥；请求由应用从这台手机发出（开着 VPN 时走 VPN），仅 https、只接受公网地址，抓取可选“渲染”（用 App 的浏览器引擎加载后再抽取，页面脚本会执行）。默认关闭，助手仍须显式选择；本机抓取是第三个被批准的例外（见 §6.2），每段对话首次调用要授权，仅用于读取文本、不保存文件、不执行页面内容；返回内容是不可信第三方文本。开关关闭时两个工具从选择器、请求和能力缺口报告里全部消失。
- URL 下载（`download_url`）：默认关闭；打开后助手仍须显式选择，每段对话首次调用弹专用授权，显示 URL 与 host 并说明 URL 可以把数据带出去；授权后走普通工具策略，聊天菜单可撤销，全局关闭清空所有授权。仅 https，单文件 64 MiB，只接受公网地址（DNS 解析和每次重定向都检查），落在 `downloads/`，走工作区配额与预留空间，不覆盖同名文件。它是第二个被批准的例外，见 §6.1。
- B 站只读（免费外部读取）：9 个匿名工具——搜索视频/专栏/UP 主/番剧（可按时长、发布时间、分区筛选）、读视频公开信息与相关推荐、读视频或专栏评论及单条楼中楼、读专栏正文、读 UP 主主页（资料/粉丝/投稿/合集/动态）、读榜单/热门/热搜、读番剧季信息与分集、读直播间状态、抽样读弹幕——**不需要 B 站账号、不需要密钥、不花钱**；请求由应用代助手发出，助手自身仍没有网络，工具参数只有 BV/cv/ss/ep 号、mid、房间号或关键词、没有 URL。默认关闭：Settings 全局开关 + 助手显式选择两层，开关关闭时从选择器、请求和能力缺口报告里全部消失；`null` 的"全部"不会包含它们。不提供任何以用户身份发布、收藏、私信或读取账号数据的能力。B 站公开网页接口非官方，可能限流、变更或失效；返回内容是不可信第三方文本；弹幕是 B 站按分段返回的抽样，结果会说明抽样了哪几段，不会冒充全部弹幕。
- 可选的 B 站只读登录：设置里扫码后，助手可以读视频字幕（带每句起始时间，可按时间窗分段读）、B 站自己的 AI 总结，以及第 2 页以后的评论（第 10 个工具 `bili_transcript`）。只保存读接口需要的两个 Cookie，**不保存发评论用的写令牌**，不进备份/诊断、可随时断开；未登录时这个工具不出现。它不读历史、收藏、关注或私信——那些属于账号数据，不是公开内容。
- 图片生成、视频生成、语音合成、音频转写和决策分类是**逐项可配置**的付费媒体工具：可以沿用助手的服务商、选择已配置的通义 Token Plan 服务商与模型（语音合成/音频转写也可以用已配置的 DeepSeek 服务商，它的 ASR/TTS 接口不需要模型），或单独填写兼容 API 和密钥；按调用计费。后端不支持该能力、缺密钥或未配置时，这些工具**不出现在清单里**，而不是一行灰色。
- 聊天菜单里的手动媒体入口（生成图片/视频、语音合成、决策、转写音频）和对应的对话框同样带 `PAID` 标记与计费说明；披露不等于审批，是否先问仍由用户的审批规则决定。
- 付费和远程能力都不会因为“默认不审批”而被隐藏；披露和审批是两件事。

### 6. 数据、安全与恢复

- 本地优先、单用户、不需要账号；数据保存在本机。
- 密钥保存在系统安全存储里，不进入备份包；聊天服务商（含内置 DeepSeek）、网页搜索/抓取和付费媒体后端的已保存密钥都可以在设置里显式删除，OAuth 登录用登出撤销。
- 加密备份：可以用口令导出和导入；支持在设置中选择并记住一个**同步文件夹**（如 Syncthing、Nextcloud 或网盘目录，系统持久授权），之后点“备份到此文件夹”（或从首页到期提醒点“去备份”）只需输入口令即可直接写入带时间戳的新加密备份文件（`inhuman-backup-YYYYMMDD-HHmmss.ibak`），不覆盖旧文件，也可随时“另存为文件…”；导入前显示预览（对话数、消息数、工作区数、导出时间），替换后保留一次“撤销上次导入”。
- 版本升级保留数据；备份恢复在数据被打开之前完成，失败会回滚。
- 诊断日志：记录回合、工具调用、失败和崩溃；用户可以查看大小、分享、清空；不记录密钥、提示词、文件内容。
- 应用内更新（手机端）：设置里有独立的**更新服务器**和**上传服务器**两个地址。更新服务器可以从三个**内置地址**里一键填入（项目自己的 GitHub Releases `releases/latest/download`，直连加两个国内镜像），也可以填自己的服务器；检查 `update.json`、下载 APK，校验 SHA-256、包名、版本号和签名后交给系统安装器，系统仍会要求确认，不会静默安装。下载并校验过的 APK 会留在应用缓存里，再次检查会复用它，不会重新下载。
- 日志上传（手机端）：使用**上传服务器**（通常是局域网或 Tailscale 上的 dev-server，与更新服务器可以不同），用户点“上传日志”时把诊断日志 POST 到 `/log`；只在点击时发生。**上传对话**是另一个入口和另一个端点 `/conversation`，同样使用上传服务器，发送的是明文对话 Markdown，必须先经过带有服务端地址和内容说明的预览确认；它不混进诊断日志。更新、日志上传和对话上传都是用户操作的应用功能，不是助手的工具；助手仍然没有网络。
- 手机端每个对话的后台进度独立通知；可以单独停止，也可以全部停止；等待授权时可以直接从通知回到对话。

### 7. 平台与体验

**手机（Android）**

- 手机/平板自适应：单栏、双栏、悬浮按钮/标题栏/顶栏按屏幕宽高切换。
- 系统文件管理器可以直接浏览工作区；可以用外部编辑器打开并保存。
- 后台回复有常驻通知；锁屏、切后台不容易被系统杀掉。
- 中英文双语；默认中文，可在设置的“语言”里切换英文（系统“应用语言”也会生效）。
- 配色与底材：默认余烬（焦橙）＋暖石墨/暖纸，设置 → 10 / 显示 还可选择苔绿、靛蓝、紫檀三种强调色，暖/冷灰/棕墨三种底材（石墨与纸的质地），以及独立的“跟随系统 / 始终浅色 / 始终深色”。强调色只换信号色；底材会把背景、表面、分隔线、中性文字整组一起换，不会出现文字与背景来自不同套色；字体、间距与圆角始终不变。这是纯外观选择，不改变工具、审批或任何能力。每个配色 × 底材 × 深浅都有对比度单测。

- 不要求广泛存储权限。

#### 新增能力的边界说明

- **从其他工作区导入文件**：只扩大**用户**能从哪儿取文件，不扩大**助手**能看到的目录——上传时多一个来源，字节仍然被复制进目标工作区，源工作区一个字节都不动，助手看到的还是目标工作区的相对路径（绝对路径从来不给模型）。配额、单文件上限、重名“ (2)”的编号规则和普通导入完全一致。代价要说清楚：那是**快照**，之后源工作区里改了同一个文件，目标工作区里这份不会跟着变；想要新的，再传一次。
- **跨工作区导入不能做成引用**：不能靠“引用/挂载另一个工作区的文件”省掉那份复制——同一个文件会同时出现在两段对话的目录里，一个工作区的还原点回滚就会写到另一个工作区的东西上；而且它得先放松“路径解析只认工作区内的真实路径”这条唯一的落地检查，隔离就只剩声明。
- **保存提示词**：库存的是**用户写给助手看的文本**，属于助手配置，不是助手的能力——模型读不到这个库，也不能写它，或把某一段设成自己的系统提示；被选中的一段只是填进系统提示框，之后照样可以改。诊断日志不记录提示词内容，这条对保存的提示词同样成立。工坊的配置读/提案工具同样不碰提示词库。
- **工坊**：它把“用户配置”和“角色扮演素材”当成内容交给 agent 起草，但**写入权没有转移**——工具只返回草稿，点按只打开用户原本就有的编辑器，保存仍是那一个手势；场景提案也只有用户点“创建并打开”才创建对话。提案里没有工具、服务商、模型、审批、SSH 或下载授权，所以 agent 不能借它调整自己的能力上限；工作区以显示名寻址，目录 id 不进请求；提示词库仍然读不到、写不了；工坊本身不可改名、不可删除，也不能被批量删除。跨工作区能碰到的只有每个永久工作区根目录的 `AGENTS.md` 这一个文件名，读也经该工作区自己的路径检查。
- **建议回复**：它仍然是回答的**形状**，不是助手能碰到的东西——`suggest_replies` 没有工作区、没有文件、没有网络，只把最后一问一答发给建议模型，结果也只变成输入框里的候选。但它现在**会花一次额外请求**，所以默认关闭，且要过两道门：设置 → 显示的全局开关，和助手工具列表里的显式勾选；“全部”不会包含它（和 SSH 同一条规则：新名字出现不能自动给旧对话加钱）。花钱要在选择的地方看得见：PAID 徽标、账单提示、助手编辑器里那句“每次调用多一次请求”。三条线仍然不能松：候选只是**填进输入框**（可改、可丢），绝不自动发送；点一条**不等于授权**——一次授权、一次审批都只在它们自己的界面里发生；助手觉得没什么可说时可以不提供。工具结果和调用都会留在对话记录里，不假装没发生过；`endsTurn` 让这一回合在建议返回后结束，不再让主模型复述一遍。
- **从其他应用分享文件进来**：入口是**用户**在别的应用里点的那一下“分享”，不是别的应用能自己调用的能力——一次一份，收到就复制，仍然走配额和重名规则；它不能远程触发，也不给任何应用留下一条读工作区的路。
- **导出是明文的出口**：故意明文（要能给别人看、能用别的工具打开），所以只能导出用户点名的那一段对话或那一个工作区；可以定期的是**加密备份**，不是这个明文出口。
- **用量总览和备份提醒只读**：看数据、提醒你，不改变任何现有行为，也不新申请权限（备份目录用你已通过系统授权的那一个）。提醒可以关掉，关掉就是现在这样，不会悄悄少一个保护。
- **文档能力**：它只是让“读工作区里的文件”这件事更深，不是更远——文档还是工作区里的文件，产出的新文件也落在工作区，能被还原点回退。真正的风险不是越界，而是**读错了还说读对了**，所以“不悄悄丢内容”是这一条的第一要求。
- **语音输入**：录音在本机，转出来的文字进的是输入框，用户按发送才算数。它不给助手增加任何能力，也不需要额外的开关——不给麦克风权限，就等于没有这个功能。

#### 文档能力：要什么，不写怎么实现

- **第一批格式**：PDF、DOC、DOCX、XLS、XLSX、CSV。之后按“用户真的会带来”继续补（例如 PPT、ODT），不预先列一长串承诺。
- **读**：正文、标题层级、列表、表格的行和列；PDF 按文本层读。读完用户应该能说清助手到底看到了什么，而不是只知道它翻到了第几页。
- **写**：能创建上面这些格式的新文档；能修改已有的文档，改完那份要还能被 Word、Excel 或阅读器正常打开。
- **转换**：这些格式之间能互转；每次转换都要报告**丢了什么**（排版、公式、批注、宏、嵌入对象），不能看起来成功、内容却没了。
- **读不全、写不全、转不全时必须说出来**，并指出缺的是哪一部分。这条比“支持多少种格式”重要。
- **大文档要可预期**：几百页的东西不能整份塞进上下文然后失败；要能明确地“只读一部分”。
- **扫描件、拍照件**（没有文本层的 PDF）：已决定不放进第一批本地格式，改为两条 opt-in 付费读取——`read_pdf_vision` 用当前视觉模型（≤4 页/次），`read_scanned` 用 DeepSeek OCR（≤10 页/次、上传文件、按页计费，见 `docs/03-ai-provider.md`）。本地 OCR 引擎仍不在范围内。
- **技术路线未定。** 如果某种格式的处理要花钱，按第 5 条披露；不花钱就不标。

#### 语音输入：要什么，不写怎么实现

- **输入框里一个入口**：按下开始录、松开结束；接近时长上限时要提前提示，而不是录完才说不行。
- **说完的字进输入框**，能改、能取消，**不自动发送**。
- **第一次用才申请麦克风权限**；拒绝了，打字和别的一切照常，不反复弹。
- **录音默认不留**：转写完就丢，不进工作区、不进对话记录，除非用户明确要保存。
- **转出来的文字是用户自己说的话**，按用户输入的身份进对话，不能被当成助手的建议回复。
- **转写会花钱**（如果所用的能力按调用计费）：这一点要在录音之前就能看到，而不是等账单。
- **技术路线未定。**

### 2. 明确不做

- 不存在解锁本地权限、访问工作区之外的开关；本地能力就是工作区，远程操作能力就是默认关闭的 SSH。
- Android 上不做 Linux 命令行环境。
- 不申请广泛存储权限。
- 不把“保存远程信息”包装成安全或隐私保障；它只是省去重复输入。
