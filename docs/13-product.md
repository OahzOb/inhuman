# inhuman — 产品说明

> 本文只描述产品层面的**设计原则、已有功能和未来规划**。它不涉及具体技术栈、框架、模块划分，或某个功能的代码实现；但保留通用的协议名、服务名和计算机术语（如 SSH、MCP、token、检查点），因为它们是产品能力的一部分。技术实现见 `docs/` 的其他文档。

## 一句话

**inhuman 是一个本地优先的智能助手：每段对话都在一个工作区里运行，助手只能在这个工作区里读写文件；默认不打断你；唯一能让助手在另一台机器上执行操作的，是你明确打开的远程能力。**

它是单用户的、不需要账号的、把“能力边界”当作产品本身来做的工具。

---

## 一、设计原则

### 1. 工作区是产品的边界

- 每段对话绑定一个工作区；助手只能看到、只能改这个工作区。
- 这不是靠提示词要求模型“别乱来”，而是产品只给它这个入口：它拿不到工作区之外的位置。
- 用户导入文件是**复制**，不是移动；原件永远不动，也不在目录里。所以工作区里导入的文件坏了、删了，原件还在。
- 结论：工作区内的操作默认是可逆的；这才有第 3 条“默认不审批”。

### 2. 本地能力硬隔离，外部能力默认关闭

- Agent 的本地能力被硬限制在工作区内：它只能读写这个工作区，拿不到工作区之外的路径。唯一的远程操作能力是 SSH，默认关闭。
- 没有“解锁更多本地权限”的开关，也没有“高级模式”或可累积的权限等级；能力边界不靠用户选择档位来改变。
- 要避免的是**由权限开关造成的会话不连续**：每执行一条命令问一次、每换一个模式就改变对话的含义、每加一个能力就多一个需要用户理解的档位。这些会把一次对话切成一串审批，也会训练用户无脑点过。
- **工具清单按回合固定**：只有用户能在回合边界改变一段对话的工具清单；模型不能给自己加能力，消息和工具结果也不能。改动从下一回合生效，不会在流式回答中途改变规则。
- 对 SSH 这类高风险能力，默认走**一次性的能力授权**：第一次调用时，用最强的提示说明主机、用户和第一个操作；用户确认后，这段对话就获得用户所选中的 SSH 工具的使用授权，之后按普通规则执行，默认不再逐条询问。
- 工具清单和 SSH 授权是两层：清单决定这个回合有哪些工具；授权只回答“这段对话能不能用清单里选中的远程工具”，不会把未选中的 SSH 工具加进来。
- 为什么不是逐条问：用户通常无法判断一串 shell 命令该不该执行；对一条命令问“确定吗”，得到的往往不是判断，而是习惯性点击。一次授权加可撤销，比一百次无法回答的询问更接近真实的安全。
- 这不是设备级权限：授权范围是**这段对话 + 用户选中的 SSH 工具**，不是设备、不是本地文件系统、不是所有对话；用户可以随时撤销，关闭全局开关会清掉所有授权。所谓“最高权限”，是这组工具授权范围内的最高，不是设备级的最高。
- 但“询问”仍然是用户的权利：用户可以把任意工具、任意助手、任意路径设成“询问”；默认不问，不等于不能问。默认只是“不主动打断”，是否打断由用户决定。
- 判断标准：新增一个能力时，不要新增一个“模式”或“权限档位”；如果要问，就问一次、问在能力被授予的地方，而不是在每条命令前重复问。

### 3. 默认不打扰

- 默认不弹审批，包括删除文件。
- 用户想更谨慎时，可以按工具、按助手、按路径收紧；多处规则同时生效时，**取最严**。
- 默认不问，不等于“永远不问”：询问是用户的权利。用户可以要求每次调用都问；代价是会话会被打断，所以这个选择由用户显式做出，而不是产品默认。
- 没有“删除永远要问”的地板；用户是工作区的主人，包括决定删文件要不要问。
- 为什么：工作区里是副本，问“确定吗”答案永远是“确定”；一个总是得到同一个答案的对话框不是安全措施，是摩擦。审批疲劳会让真正需要确认的时刻被无脑点过。
- 审批是**可选的收紧手段**，不是主要安全机制；主要机制是第 1 条的结构。

### 4. 用户对自己的数据有主权

- 用户永远能读写自己的工作区；路径规则只限制助手，不限制用户。
- 工作区的绝对位置只给用户看，不进入模型上下文。
- 用户可以通过应用导入、导出、编辑，也可以用系统文件管理器或外部编辑器打开。
- 应用不要求广泛存储权限，也不接管用户的整个文件系统。

### 5. 花钱和远程必须显眼

- 付费工具在**选择它的地方**和**使用它的地方**都有明确标记和说明；价格不写在没人展开的描述里。
- 付费披露不等于审批：默认仍然不问，是否先问由用户规则单独决定。
- 远程能力有独立标记；它不能混进本地工具列表里，也不能靠“全选”被顺带打开。
- 这条对以后所有“调用第三方付费服务”或“影响设备之外”的能力都生效，不只是现在这些。

### 6. SSH 是唯一被批准的远程操作例外

- 默认关闭，而且是多层关闭：全局开关默认关；即使打开，助手还必须显式选中要用的每一个远程工具；第一次调用时，对话里再授权一次。
- 首次授权后，默认不再逐条询问；如果用户把 SSH 的规则设成“询问”，才会逐条确认。授权是能力授予，审批是单次许可，两者可以叠加，但默认只需要前者。
- 网页搜索/抓取由应用代用户发请求，不把网络交给助手；SSH 不同，它让助手在另一台机器上读、写、执行。
- 目前应用不提供主机列表、不保存凭据，也不管理远程设备；地址和密码/密钥由用户告诉助手。规划中加入“保存远程信息”，目的只是省去重复输入，不构成对凭据的安全/隐私保证（见第三节）。
- 只读组合（探测、列目录、读文件、下载）可以不开命令执行；一旦加入执行命令、上传或写远端，授权会重置，下一次重新确认。
- 凭据参数在写入会话前隐藏；命令文本、路径和写入内容会留在会话里，这是会话本身。
- 风险在远端，不在工作区副本：远端删除、覆盖、改权限都可能不可逆。所以远程写操作不提供回退。
- 这不是设备级权限：没有本地权限提升，没有可累积的权限层级，只有一个用户显式打开、按对话授权、可撤销的远程通道。

### 7. 可逆与不可逆要分清

- 本地文件操作可还原：每个回合、每个完成的工具组都有还原点（checkpoint）；可以回到“你的消息之前”或“某个工具组之后”。
- 不可逆的远程操作（执行命令、上传、写远端）不提供回滚；含这些操作的回合只允许重新回答，不允许“编辑消息”。
- 还原点按回合保留，用户可以选择保留 1/3/5/10 个回合；回退前会列出会改动哪些文件。

### 8. 中断、崩溃、重开都不能悄悄丢东西

- 已经收到的回答，即使你按停止，也会保存；不会因为“停止”丢掉已经计费的部分。
- 进程被杀、断电、旋转屏幕、切后台，不能出现“回答没了”或“下一条消息报错”。
- 备份恢复在应用启动、数据被打开之前完成；失败会回滚旧数据。
- 每个对话的进度通知互相独立；停止一个不会停错另一个。

### 9. 安全声明必须能被审计

- 开源；围栏有自动化测试；文档记录为什么这样做。
- 诊断日志给用户看、可导出；但**不记录密钥、提示词、文件内容**。
- 能力边界要能一句话说清；说不清的能力不加。
- 一个自称安全却不可审计的实现，说服力有限；这是开源的真正理由。

### 10. 轻量、移动优先

- 手机是主产品；桌面是同一能力的第二个宿主，不是把手机做成桌面。
- 不为了桌面把手机做重：不移植桌面专属的插件系统、多主机配置和网页版界面。
- 不做 Android 上的 Linux 命令行环境；不做广泛存储权限。
- 性能预算可以调（工具轮数、调用次数、远程资源上限）；**权限边界不可调**。

### 11. 工作台，不是聊天模板

- 视觉是“暖纸/暖石墨 + 一个信号橙”；等宽字体只用于元数据，不用于正文。
- 用细线分隔，不用满屏卡片；网格只出现在空画布上。
- 宽屏要限制阅读宽度并居中；手机、平板、横屏、方屏都要实际验证，不能只验一种。
- 主操作在手机上可以是悬浮按钮，在中等宽度是标题栏，在双栏是顶栏；同一功能在不同尺寸下用不同位置，是设计，不是不一致。

### 12. 说到的必须做到

- 文档、界面文案、工具描述不能承诺产品没做的事。
- 如果文案和实际行为不一致，按缺陷处理，而不是“改文案了事”。
- 改行为就改文档；否则下一次会有人按旧文档做错决定。
- 新功能先对照这份原则：它是否扩大了助手能碰到的范围？如果是，就需要新的“一句话例外”、披露和授权，而不是一个设置项。

### 13. 桌面端不能拖 Android 的后腿

- Android 是主产品；桌面端是第二个宿主，不是前置条件。
- 桌面端不能拖慢 Android 的功能、发布或工具链升级。如果它开始拖，就分开做，而不是让 Android 等它。
- 分开不等于降低标准：两边都必须满足这份文档的设计原则和能力边界——工作区硬隔离、没有完全访问、工具清单按回合固定、默认不审批但可询问、付费/远程披露、SSH 例外，以及数据/备份兼容。
- 如果连共享运行时也要各写一份，就必须用一致性测试证明这些边界；证明不了，就不是“分开”，是把产品拆成了两个不同的产品。

### 判断新功能该不该做

1. 它是否扩大了助手能碰到的东西？如果是，先写一句用户能读懂的能力声明，并为它设计披露和授权；不要直接加设置项。
2. 它是否引入了一个“可以要更多权限”的入口？如果是，不做。
3. 它是否可逆？不可逆就明确标记，并且不提供回退。
4. 用户能不能自己验证它？不能验证的能力，先补日志/审计。
5. 它是否只在桌面成立？如果是，先问“手机用户是否也需要”；不需要就不做。
6. 它是否用反复询问来代替一次性能力披露？如果是，改成一次授权。它是否让默认状态多了一次打断？默认仍然是“不打断”，把选择权交给用户。
7. 它是否会让桌面端成为 Android 的前置条件？如果是，先按第 13 条处理：要么解耦，要么分开。

## 二、已有功能

### 1. 对话与回答

- 流式回答；显示推理过程（模型提供时）、Markdown、代码高亮、token 用量。
- 上下文仪表：显示上下文窗口用了多少；可以显式压缩旧回合（保留最近两个完整回合，更早的用摘要替代），也可以恢复完整历史。
- 分支：重新生成保留旧答案，可以切换。
- 重做与回退：重新回答、从你的消息重来、从某个工具组之后重来、编辑你的消息；还原点；改动文件列表。
- 搜索对话标题和消息内容，跳转到具体消息并高亮。
- 会话内搜索（手机端）：全屏搜索当前对话的用户和助手正文，跳过工具结果；列出匹配数和每条摘要，点一条跳到该消息并高亮。
- 回合快速跳转（手机端）：对话上方的“回合 n/m”显示当前位置；点开是用户消息列表，点一条直接跳到那个回合，当前回合在列表里标出。
- 在对话内直接新建对话（手机端）：顶栏的“+”用当前助手新开一段对话；当前是永久工作区时新对话共享它，临时工作区则新建一个。
- 置顶、重命名、删除；手机端支持多选删除。
- 错误恢复：重试、压缩后重试、去模型服务设置、复制详情；没有“只能关闭”的死胡同。
- 图片附件：最多 4 张；先检查模型是否支持视觉，再发送。
- 请求原文查看器（手机端）：可以看到系统提示、工具定义、消息和原始工具调用。
- 演示模式：没有密钥也能跑通工具循环、结果和收尾总结。
- 导出：单段对话可导出 Markdown（可选是否包含工具调用与结果；推理过程一并写出；附件只列路径，不复制文件）；工作区可导出 zip（对话菜单和工作区详情都可，临时和永久工作区都覆盖）。导出是明文，保存位置由用户选择，不能当备份。

### 2. 助手与模型服务

- 助手：一个可保存的“人设”，包含名称、系统提示、模型服务（provider）、模型、推理强度和工具清单。
- 每段对话选择一个助手；对话创建时复制当时的模型服务和模型，之后编辑助手不会改变已有对话。
- 模型服务：内置 DeepSeek；可以添加兼容 OpenAI 接口的第三方服务；每个助手选择一个服务；模型列表从服务读取；密钥按服务保存。
- 推理强度按对话可调（服务支持时）。

### 3. 工作区与文件

- 工作区有两种：**临时**（随对话创建和删除）和**永久**（对话删了也保留，可以被多个对话共享）。
- 永久工作区有共享配额：约 256 MB、5,000 个文件；单文件写入约 4 MB，单次读取约 1 MB，列表最多 500 项。
- 8 个文件工具：列目录、读文件、写文件、追加、建目录、移动/重命名、删除、查看文件信息。
- 路径规则四档：自由、询问、**拒绝**（任何调用都被挡下，文件名仍然可见）、**不可见**（连文件名都不出现在助手的列表里）。
- 用户可以把文件导入工作区、导出、在应用内编辑、用系统程序打开。
- 手机端还可以从 URL 把文件下载到工作区或用户选择的目录；桌面端未提供这一入口。
- 工作区的绝对位置只给用户看；助手始终只看到工作区内的相对路径。

### 4. 工具与审批

- 共 24 个工具：8 个文件工具、时间、2 个付费联网工具、决策、转写、4 个媒体工具（图片、视频、视频状态、语音）、7 个远程工具；其中 7 个按调用计费。
- 每个会改变状态的工具都带“可回退/不可回退”标记；付费工具带“付费”标记；远程工具带“远程”标记。
- 审批默认全部“自由”；用户可以在三个层面收紧：全局、按助手、按路径；同时生效时取最严。
- “询问”是用户可选项：可以把任意工具设成询问；默认不问是为了不打断会话，不是禁止用户收紧。
- “拒绝”和“不可见”是**拒绝执行**，不是“再问一次”；它们排在“询问”之前。
- 每段对话可以有自己的工具清单：助手是上限，只有用户能改，改完从下一回合生效；模型不能改。
- 工具预算：默认每回合最多 8 轮工具、32 次调用；用户可以调高或调低。
- 用量总览：设置 → 05 / 用量，按今天、7 天、30 天、全部汇总本机仍保存的输入/输出/缓存/推理 token，以及 7 个付费工具的调用次数；按天和按对话列出。只统计当前仍保存的记录，已删除或回退的回合、压缩摘要不计入；不换算价格。

### 5. 远程与付费能力

- 远程（SSH）：7 个工具，覆盖探测主机、列目录、读文件、执行命令、上传、写远端文件、下载。
- 默认关闭；全局开关 + 助手显式选择 + 每对话首次授权，三层。
- 首次授权后默认不再逐条询问；用户把 SSH 工具设成“询问”时才会逐条确认。
- 目前不提供主机列表、不保存凭据；主机指纹首次连接时记住，变更时拒绝连接。规划中加入远程信息保存，目的只是省输入，不是安全/隐私保证。
- 远程资源有用户设定的上限：命令超时、输出大小、目录行数、文本读取量；模型只能请求更小，不能更大。
- 联网搜索/抓取：可以分别选择 DeepSeek 或 Exa；使用独立的密钥，和聊天用的密钥分开；按调用计费。
- 图片生成、视频生成、语音合成、音频转写和决策分类是**逐项可配置**的付费媒体工具：可以沿用助手的服务商、选择已配置的通义 Token Plan 服务商与模型，或单独填写兼容 API 和密钥；按调用计费。后端不支持该能力、缺密钥或未配置时，这些工具**不出现在清单里**，而不是一行灰色。
- 付费和远程能力都不会因为“默认不审批”而被隐藏；披露和审批是两件事。

### 6. 数据、安全与恢复

- 本地优先、单用户、不需要账号；数据保存在本机。
- 密钥保存在系统安全存储里，不进入备份包。
- 加密备份：可以用口令导出和导入；导入前显示预览（对话数、消息数、工作区数、导出时间），替换后保留一次“撤销上次导入”。
- 版本升级保留数据；备份恢复在数据被打开之前完成，失败会回滚。
- 诊断日志：记录回合、工具调用、失败和崩溃；用户可以查看大小、分享、清空；不记录密钥、提示词、文件内容。
- 应用内更新（手机端）：在设置里填一个局域网或 Tailscale 服务器地址，检查 `update.json`、下载 APK；校验 SHA-256、包名、版本号和签名后交给系统安装器，系统仍会要求确认，不会静默安装。下载并校验过的 APK 会留在应用缓存里，再次检查会复用它，不会重新下载。
- 日志上传（手机端）：同一个服务器，用户点“上传日志”时把诊断日志 POST 到 `/log`；只在点击时发生。更新和日志上传都是用户操作的应用功能，不是助手的工具；助手仍然没有网络。
- 手机端每个对话的后台进度独立通知；可以单独停止，也可以全部停止；等待授权时可以直接从通知回到对话。桌面端用托盘提醒。

### 7. 平台与体验

**手机（Android）**

- 手机/平板自适应：单栏、双栏、悬浮按钮/标题栏/顶栏按屏幕宽高切换。
- 系统文件管理器可以直接浏览工作区；可以用外部编辑器打开并保存。
- 后台回复有常驻通知；锁屏、切后台不容易被系统杀掉。
- 中英文双语；默认中文，可在设置的“语言”里切换英文（系统“应用语言”也会生效）。
- 不要求广泛存储权限。

**桌面（Windows）**

- 独立安装包和独立数据目录；卸载应用不会删数据。
- 单实例；系统托盘；键盘快捷键；中英文切换；拖放文件；系统文件对话框；用系统程序打开文件。
- 与手机共享同一套工作区结构和备份格式；但两端是各自机器上的数据，不是实时同步。

**桌面端目前比手机少**

- 没有永久工作区的管理界面；
- 没有让系统文件管理器直接浏览工作区的集成；
- 没有会话内搜索、回合快速跳转和对话内新建对话；这些目前只在手机端；
- 没有应用内更新和日志上传；这些目前只在手机端；
- 少量错误信息还是英文；
- 没有 Linux 版本；
- 没有在真实远程主机上做过完整验证。

#### 新增能力的边界说明

- **从其他工作区导入文件**：只扩大**用户**能从哪儿取文件，不扩大**助手**能看到的目录——上传时多一个来源，字节仍然被复制进目标工作区，源工作区一个字节都不动，助手看到的还是目标工作区的相对路径（绝对路径从来不给模型）。配额、单文件上限、重名“ (2)”的编号规则和普通导入完全一致。代价要说清楚：那是**快照**，之后源工作区里改了同一个文件，目标工作区里这份不会跟着变；想要新的，再传一次。
- **跨工作区导入不能做成引用**：不能靠“引用/挂载另一个工作区的文件”省掉那份复制——同一个文件会同时出现在两段对话的目录里，一个工作区的还原点回滚就会写到另一个工作区的东西上；而且它得先放松“路径解析只认工作区内的真实路径”这条唯一的落地检查，隔离就只剩声明。
- **保存提示词**：库存的是**用户写给助手看的文本**，属于助手配置，不是助手的能力——模型读不到这个库，也不能写它，或把某一段设成自己的系统提示；被选中的一段只是填进系统提示框，之后照样可以改。诊断日志不记录提示词内容，这条对保存的提示词同样成立。
- **建议回复**：改的是回答的**形状**，不是助手能碰到的东西——还是同一次回答，多的只是末尾几条候选文本，没有新工具、没有新路径，也不额外跑一次请求（否则每句话的价钱翻倍，这是约束不是建议）。但它在用助手的口吻替用户说话，所以三条线不能松：候选只是**填进输入框**（可改、可丢），绝不自动发送；点一条**不等于授权**——一次授权、一次审批都只在它们自己的界面里发生，一句看着像“同意”的建议文本不能替用户完成；助手觉得没什么可说时可以不提供，不硬凑。这个开关是**显示偏好，不是能力档位**：开着不会让助手多做到任何事，关掉就回到现在的样子——回答后面干干净净。
- **从其他应用分享文件进来**：入口是**用户**在别的应用里点的那一下“分享”，不是别的应用能自己调用的能力——一次一份，收到就复制，仍然走配额和重名规则；它不能远程触发，也不给任何应用留下一条读工作区的路。
- **导出是明文的出口**：故意明文（要能给别人看、能用别的工具打开），所以只能导出用户点名的那一段对话或那一个工作区；可以定期的是**加密备份**，不是这个明文出口。
- **用量总览和备份提醒只读**：看数据、提醒你，不改变任何现有行为，也不新申请权限（备份目录用你已通过系统授权的那一个）。提醒可以关掉，关掉就是现在这样，不会悄悄少一个保护。
- **文档能力**：它只是让“读工作区里的文件”这件事更深，不是更远——文档还是工作区里的文件，产出的新文件也落在工作区，能被还原点回退。真正的风险不是越界，而是**读错了还说读对了**，所以“不悄悄丢内容”是这一条的第一要求。
- **语音输入**：录音在本机，转出来的文字进的是输入框，用户按发送才算数。它不给助手增加任何能力，也不需要额外的开关——不给麦克风权限，就等于没有这个功能。

#### 文档能力：要什么，不写怎么实现

- **第一批格式**：PDF、DOC、DOCX、XLS、XLSX、CSV。之后按“用户真的会带来”继续补（例如 PPT、ODT），不预先列一长串承诺。
- **读**：正文、标题层级、列表、表格的行和列；PDF 按文本层读。读完用户应该能说清助手到底看到了什么，而不是只知道它翻到了第几页。
- **写**：能创建上面这些格式的新文档；能修改已有的文档，改完那份要还能被 Word、Excel 或阅读器正常打开。
- **转换**：这些格式之间能互转；每次转换都要报告**丢了什么**（排版、公式、批注、宏、嵌入对象），不能看起来成功、内容却没了。
- **读不全、写不全、转不全时必须说出来**，并指出缺的是哪一部分。这条比“支持多少种格式”重要。
- **大文档要可预期**：几百页的东西不能整份塞进上下文然后失败；要能明确地“只读一部分”。
- **扫描件、拍照件**（没有文本层的 PDF）算不算第一批，待定。
- **技术路线未定。** 如果某种格式的处理要花钱，按第 5 条披露；不花钱就不标。

#### 语音输入：要什么，不写怎么实现

- **输入框里一个入口**：按下开始录、松开结束；接近时长上限时要提前提示，而不是录完才说不行。
- **说完的字进输入框**，能改、能取消，**不自动发送**。
- **第一次用才申请麦克风权限**；拒绝了，打字和别的一切照常，不反复弹。
- **录音默认不留**：转写完就丢，不进工作区、不进对话记录，除非用户明确要保存。
- **转出来的文字是用户自己说的话**，按用户输入的身份进对话，不能被当成助手的建议回复。
- **转写会花钱**（如果所用的能力按调用计费）：这一点要在录音之前就能看到，而不是等账单。
- **技术路线未定。**

### 2. 明确不做

- 不存在解锁本地权限、访问工作区之外的开关；本地能力就是工作区，远程操作能力就是默认关闭的 SSH。
- Android 上不做 Linux 命令行环境。
- 不做 Linux 桌面版。
- 不申请广泛存储权限。
- 不把“保存远程信息”包装成安全或隐私保障；它只是省去重复输入。
